## Problem & user

RocketShip PMs need this handled: Juno is an AI Associate Product Manager for RocketShip. It reads, clusters and proposes, and it never changes anything. It has read-only access to Jira, Slack and Notion, and every action that changes something is a human’s decision. Each week, find untouched Jira, Slack and Notion items that describe the same underlying problem, rank the clusters by breadth or exposure and give the PM a short digest. The digest contains:  proposed merges, each with linked evidence, for the PM to approve or reject auth issues, escalated to a human and never resolved by Juno items that need clarification before they can be clustered.. Juno does this inside limits a human set on purpose, and defends every call it makes.

## 01 Context · Data Requirements

**Required sources, and exclusions**

INPUTS TO CLUSTER
- Untouched Jira tickets, Slack requests and Notion docs past a set window (proposal: 14+ days).
- Break items down to the problem level. One item can hold several problems (e.g. a 403 error plus a missing invoice). Ignore anything described as working fine.

REFERENCE DOCUMENTS (read fresh each run)
- Product Strategy: P0-P3 priority framework, used for ranking.
- Product Roadmap: shows whether a problem is committed, planned or unmapped.
- Sales Pipeline Snapshot: ARR, renewal dates and deal deadlines, used for exposure.

DELIBERATELY LEFT OUT
- Engineering Capacity Note: Juno does not make capacity judgments. It also contains personal staff details that do not belong in a digest.
- Recently active items.
- Anything in the done/completed column.

EACH RUN RECORDS
- A sync timestamp and an item count per source.
- An "as of" date for each reference document.

**How fresh must it be**

- Items: pulled daily. Untouched items change slowly, so real-time adds cost and no value.
- Reference documents: read live every run, and each must be dated within 7 days.
UNREACHABLE SOURCE
- Strategy or Roadmap unreachable: halt and route to the PM. Ranking on stale tiers could bury an at-risk renewal.
- A Jira, Slack or Notion pull fails: send the digest marked INCOMPLETE and name the missing source. Never present it as complete.

## 02 Tools · System Capabilities

**The verb list**

CAN DO
- Read Jira, Slack and Notion, plus the three reference documents.
- Cluster problems, rank clusters, and propose merges.
- Escalate new auth or access failures.
- Link problems to existing roadmap items.
- Flag items that need clarification, promise gaps and dependency conflicts.

DELIBERATELY NOT GIVEN
- Write access to Jira, Slack or Notion (no merging, closing, commenting or editing).
- Any way to message customers or colleagues.
- Drafting customer-facing statements.
VERB LIST
- read_items(source, min_idle_days): READ
- read_reference(doc): READ
- read_decision_log(): READ
- draft_digest(clusters, merges, escalations): DRAFT
- propose_merge(item_ids, evidence): DRAFT
- escalate_auth_issue(item_id, reason): WRITE (alert to the PM only)
- log_decision(merge_id, outcome): WRITE (own memory, after PM click)

**Deliberate omissions**

DELIBERATE OMISSIONS
- No merge_tickets() or update_jira(). They change the source of truth. The PM merges by hand in V1.
- No post_to_slack() or message_customer(). Anything visible to the team or a customer is the wrong place to find a tone or accuracy failure, especially after a rep already oversold a feature.
- No edit_roadmap(). Juno reads the plan and never changes it.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

- ReAct loop inside each run: reason, pull items, observe, re-cluster.
- Cap on the number of passes per run (proposal: set a fixed maximum).
- Stops early when clusters stop changing between passes.
- If the cap is hit or a source fails: stop, mark the digest INCOMPLETE with the reason, and hand back to a person.
- Never retries silently.
TURN CEILING AND ESCALATION
- Ceiling: 8 passes per run (proposal). On the last pass, return the best digest labelled "pass limit reached," never a silent truncation.
- Stop early when clusters stop changing between passes.
- Escalate to a human after 2 consecutive failed tool calls, or when reference documents contradict each other (e.g. roadmap tier vs strategy definition). Flag it with both sources cited. Never invent a tiebreak.

**Latency and cost target**

- Weekly digest: under 10 minutes (proposal). Daily coverage check and auth sweep: under 2 minutes.
- New auth alert: sent to the PM within minutes of the sweep detecting it.
- Cost ceiling (proposal, replace after measuring): $2.00 per weekly digest and $0.25 per daily check, about $15 a month.

## 04 Memory · Data Requirements

**What persists, at what scope**

STORED (only the PM writes to these)
- The done/completed column.
- Approve/reject decisions on merges, so rejected pairings do not resurface.
- Items awaiting clarification, so they are not re-flagged every run.

NOT STORED
- Strategy, roadmap and pipeline documents. They change, so they are re-read every run.
- Nothing else carries over between runs.

**Expiry and write rules**

- A PM's approve or reject is the final state and never expires. Juno's original proposal is kept alongside it, marked superseded, for audit.
- A rejected pairing stays suppressed until either item is updated or 90 days pass (proposal).
- Clarification items expire after 30 days (proposal) with one final "still unresolved" flag.
- Only the PM writes decisions. Model output never overwrites a human decision.

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

AUTONOMOUS (low damage)
- Reading, clustering, ranking, running checks, linking to roadmap items.

NEEDS PM APPROVAL
- Every merge, via on-screen approve/reject only.
- New auth or access failures: escalate, never resolve.

FLAG ONLY, NEVER DECIDE
- Disagreements between documents (e.g. roadmap rates the admin permissions fix P1, while the strategy's P0 definition covers access gaps and renewal blockers).
- Dependency conflicts (e.g. AI features that wait on the reporting table being sharded).

NEVER
- Write to source systems.
- Contact customers.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

CHECKS BEFORE THE PM SEES THE DIGEST
1. Coverage: Jira, Slack and Notion each return items with a fresh sync timestamp.
2. Freshness: Strategy, Roadmap and Pipeline docs are dated within 7 days, else roadmap links are marked "unverified."
3. Merges: each lists 2+ linked source items and a shared problem statement, else it is demoted to "needs clarification."
4. Roadmap: link problems already tracked and never propose duplicates.
5. Ranking: show tier, exposure and breadth. Tone and seniority are never inputs.
6. Auth sweep: independent pass for new access failures and escalate to the PM. 
7. Claims: label each by source (customer, engineer, sales, exec). Sales feature claims are "unverified commitment," never fact.
8. Conflicts: flag document disagreements and dependencies, citing both sources. Do not resolve them.
9. Spot-check: show a few dropped or unclustered items weekly.
STANDARD: checks 1-8 must pass.
IF A CHECK FAILS: withhold the digest or mark it INCOMPLETE with the failed check and reason at the top. Never ship quietly.

**Failure behaviour**

If Juno cannot find 2 supporting items, or a matching roadmap entry, it says "I do not have enough evidence to merge these" and moves the item to "needs clarification." It never invents a link to pass the gate. If any check fails, the digest is withheld or marked INCOMPLETE with the failed check at the top. Cautious beats guessing, and an unverified item is surfaced labelled, never quietly dropped.
