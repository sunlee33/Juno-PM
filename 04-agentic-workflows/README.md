## What Juno Is Doing

Juno’s Backlog Silencer works on insight synthesis: each week it reads untouched Jira, Slack, and Notion items, clusters the ones that are really the same problem, ranks them by tier, exposure, and breadth, and hands the PM a digest of proposed merges and escalations without changing anything itself.

## Four Levers

**Stop Conditions** (Loop):

Turn ceiling and escalation

ReAct loop inside each run: reason, pull items, observe, re-cluster.
Cap on the number of passes per run (proposal: set a fixed maximum).
Stops early when clusters stop changing between passes.
If the cap is hit or a source fails: stop, mark the digest INCOMPLETE with the reason, and hand back to a person.
Never retries silently. TURN CEILING AND ESCALATION
Ceiling: 8 passes per run (proposal). On the last pass, return the best digest labelled "pass limit reached," never a silent truncation.
Stop early when clusters stop changing between passes.
Escalate to a human after 2 consecutive failed tool calls, or when reference documents contradict each other (e.g. roadmap tier vs strategy definition). Flag it with both sources cited. Never invent a tiebreak.
Latency and cost target

Weekly digest: under 10 minutes (proposal). Daily coverage check and auth sweep: under 2 minutes.
New auth alert: sent to the PM within minutes of the sweep detecting it.
Cost ceiling (proposal, replace after measuring): $2.00 per weekly digest and $0.25 per daily check, about $15 a month.

**Confidence Thresholds** (Verification):

The check before output ships

CHECKS BEFORE THE PM SEES THE DIGEST

Coverage: Jira, Slack and Notion each return items with a fresh sync timestamp.
Freshness: Strategy, Roadmap and Pipeline docs are dated within 7 days, else roadmap links are marked "unverified."
Merges: each lists 2+ linked source items and a shared problem statement, else it is demoted to "needs clarification."
Roadmap: link problems already tracked and never propose duplicates.
Ranking: show tier, exposure and breadth. Tone and seniority are never inputs.
Auth sweep: independent pass for new access failures and escalate to the PM.
Claims: label each by source (customer, engineer, sales, exec). Sales feature claims are "unverified commitment," never fact.
Conflicts: flag document disagreements and dependencies, citing both sources. Do not resolve them.
Spot-check: show a few dropped or unclustered items weekly. STANDARD: checks 1-8 must pass. IF A CHECK FAILS: withhold the digest or mark it INCOMPLETE with the failed check and reason at the top. Never ship quietly.
Failure behaviour

If Juno cannot find 2 supporting items, or a matching roadmap entry, it says "I do not have enough evidence to merge these" and moves the item to "needs clarification." It never invents a link to pass the gate. If any check fails, the digest is withheld or marked INCOMPLETE with the failed check at the top. Cautious beats guessing, and an unverified item is surfaced labelled, never quietly dropped.

**North Star** (Context):

Required sources, and exclusions

INPUTS TO CLUSTER

Untouched Jira tickets, Slack requests and Notion docs past a set window (proposal: 14+ days).
Break items down to the problem level. One item can hold several problems (e.g. a 403 error plus a missing invoice). Ignore anything described as working fine.
REFERENCE DOCUMENTS (read fresh each run)

Product Strategy: P0-P3 priority framework, used for ranking.
Product Roadmap: shows whether a problem is committed, planned or unmapped.
Sales Pipeline Snapshot: ARR, renewal dates and deal deadlines, used for exposure.
DELIBERATELY LEFT OUT

Engineering Capacity Note: Juno does not make capacity judgments. It also contains personal staff details that do not belong in a digest.
Recently active items.
Anything in the done/completed column.
EACH RUN RECORDS

A sync timestamp and an item count per source.
An "as of" date for each reference document.
How fresh must it be

Items: pulled daily. Untouched items change slowly, so real-time adds cost and no value.
Reference documents: read live every run, and each must be dated within 7 days. UNREACHABLE SOURCE
Strategy or Roadmap unreachable: halt and route to the PM. Ranking on stale tiers could bury an at-risk renewal.
A Jira, Slack or Notion pull fails: send the digest marked INCOMPLETE and name the missing source. Never present it as complete.

## Rules of Engagement

**Agency Permission:**

Juno decides alone:

Which untouched Jira, Slack, and Notion items qualify (14+ days idle, not in the done column, not recently active).
Breaking items into problem-level pieces and clustering them.
Ranking clusters by tier, exposure, and breadth. Tone and seniority are never inputs.
Labelling each claim by source, with sales feature claims marked “unverified commitment”.
Linking problems to existing roadmap items.
Demoting any merge with fewer than 2 supporting items to “needs clarification”.
Sending new auth or access alerts to the PM.
Logging the outcome of a merge after the PM clicks.

Juno proposes and waits for the PM:

Every merge. The PM approves or rejects it on screen and merges by hand in V1.
Items flagged for clarification, promise gaps, or dependency conflicts.
Roadmap links marked “unverified”.

Juno never does:

Merge, close, comment on, or edit anything in Jira, Slack, or Notion.
Message customers or colleagues, or draft customer-facing statements.
Edit the roadmap.
Break a tie between conflicting documents.
Invent a link or evidence to pass a check.

**Access Control:**

Read only: Jira, Slack, and Notion items past the idle window.
Read, fresh every run: Product Strategy, Product Roadmap, and Sales Pipeline Snapshot.
Excluded: the Engineering Capacity Note, because Juno makes no capacity judgments and the note contains personal staff details.
Only two writes exist: an auth alert to the PM, and Juno’s own decision log after a PM click. No write credentials to Jira, Slack, or Notion exist at all.
Every run records: a sync timestamp and item count per source, and an “as of” date per reference document.

**Fallback Protocols:**

These are built so Juno can never fail quietly.

Pass limit (8) reached: return the best digest labelled “pass limit reached”. Never truncate silently.
2 consecutive failed tool calls: stop and hand back to the PM. No third try, and no silent retries.
Jira, Slack, or Notion pull fails: send the digest marked INCOMPLETE and name the missing source.
Strategy or Roadmap unreachable: halt and route to the PM, because ranking on stale tiers could bury an at-risk renewal.
Reference document older than 7 days: mark roadmap links “unverified” and say so at the top.
Documents contradict each other: flag both sources and stop. The PM decides.
Not enough evidence for a merge: say “I do not have enough evidence to merge these” and move the item to “needs clarification”.
Any verification check fails: withhold the digest or mark it INCOMPLETE, with the failed check and reason at the top.
Cost ceiling exceeded ($2.00 per weekly digest, $0.25 per daily check): stop and flag it to the PM.

**Checkpoints:**

Before any merge happens: the PM approves or rejects each proposed merge in the weekly digest.
Auth escalations: the PM acknowledges each alert, and it stays open until they do.
Conflicts and halted runs: a person resolves any document disagreement or unreachable Strategy/Roadmap before Juno continues.
Weekly spot-check: the PM reviews a sample of dropped or unclustered items to catch silent misses.
Changes to Juno’s own limits: a person signs off on any change to the idle window, thresholds, cost ceilings, or permissions.
